Data Model

The Domain in Five Entities

EntityPurposeKey relationships (logical)
OrganizationTenant boundaryHas many Users and Vaults
UserOperator identityBelongs to an Organization; owns Transactions & Signatures
VaultCustodial walletHas many Transactions & Signatures
TransactionBlockchain transferBelongs to a Vault & User; amount stored as precise decimal
SignatureSigning artifactBelongs to a Vault & User

Relationships shown are logical Go-struct associations, not database foreign-key constraints — none are enforced at the schema level today. A documented data-model cleanup item: each entity carries two identifiers (embedded gorm.Model plus a redeclared ID uuid.UUID), flagged for engineering follow-up.

How Transactions Settle

The asynchronous settlement flow splits fast request handling from background settlement. The create path is source-present but does not compile, and the automatic settlement step cannot run — it is blocked by an uninitialized-ticker panic the documentation flags for the team.
